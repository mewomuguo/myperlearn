# 15 天人身保險考試通關系統：網站功能與頁面架構 V1

版本：1.0，2026-09-25。狀態：供使用者確認的完整設計規格；尚未實作網站。

## 1. 目標、範圍與已知條件

讓零基礎使用者以每天 180 分鐘有效學習，在 Day 11 前完成 MUST 核心學習，Day 12–15 透過限時作答、錯因修正與間隔回想建立應試能力。額外 30–60 分鐘只作選做加強，休息另計。15 天是準備期，不是通過保證。

使用者已確認每天可投入 3 小時以上；正式報名名稱目前僅知「保險」。教材為人身保險實務與法規兩單元。考試日期、正式科目名稱、各科題數／時間／配分／及格規則尚未確認。這些資訊記入 ExamProfile；未核實前只提供「練習卷」，不冒稱正式模考或顯示及格判定。

完整分析 114 頁是教材製作工作，使用者的必做任務不是逐頁閱讀。全文索引供回查，首頁只引導今天下一件事。

### 本版交付及界線

- 12 章星級、262 題章末題目數、24 個 A+ 區塊、150 個學習考點、跨章重複概念與頁碼證據。
- 109 MUST、35 SHOULD、6 OPTIONAL；每點具教學成果、內容標籤、建議初學日、出題依據。
- 課表、任務引擎、錯題與弱點、準備度、數字訓練、模考、資料格式、頁面與部署驗收。
- 150 點為教學設計粒度，包含比較組；實作教材時可拆成 3–5 分鐘子卡，繼承來源及優先級。拆卡不增加該考點的統計權重。
- 本次未把 262 題逐字校訂成可用題庫，也未完成現行法規核驗。OCR 不是答案審核；疑義在分析文件列出，正式計分題須另通過內容驗收。

## 2. 講義依據及優先順序

細節見 `lecture-analysis.md`、`lecture-inventory.json`、`concept-catalog.json`。

章節重要度為設計用分數，非正式考試出題比例：

`100 × (0.60 × 星數/5 + 0.20 × 章末題數/42 + 0.10 × min(A+區塊數/5,1) + 0.10 × 跨章關聯考點數/本章考點數)`。

星級為最大權重；42 是講義最大章末题數；重複度依具體跨章考點映射，而非 OCR 關鍵字出現次數。權重是 V1 設計決策，講義原始觀察值永不被演算法改写。

MUST：四五星章的核心題型／A+重點，或後续核心所必需的基礎、跨章重複且會造成持續失分的內容。SHOULD：其餘重要補充及低星章已出題內容。OPTIONAL：低依賴歷史、統計、工具介紹。OPTIONAL 仍可能考，標籤代表有限時間下的取捨。

不能只靠所在章星級決定：風險分類及死亡率是後續前置，低星也先學；稅法不因晚出現在講義而集中塞進最後一天。A+也不是無條件 MUST，例如政府長照表仍須核對制度語境。

所有人工升降級記錄理由；同一概念跨章共用熟練度，來源與各章曝光分別保留。

### 時間與進度調整

- 第一次使用詢問開始日、考試日（可未定）、每天可用分鐘；時區預設 Asia/Taipei。
- 未定考試日顯示「15天計畫第N天／考試日期未設定」，不能冒充距離正式考試天數。
- 計畫日依開始日的當地日曆日推進，不以開啟網站次数或連續打卡決定；已過期任務不自動標完成。
- 遲到一天：先移除 OPTIONAL，壓縮 SHOULD，再把未完成 MUST 分散到剩餘 Day1–11 的時間；保留模考。若容量仍不足，顯示缺口與所需額外時間，不能假裝計畫可達成。
- 預設180分鐘切成三段，可隨時暫停續做。額外時間只挑弱點／SHOULD，不增加無關全文閱讀。

## 4. 一鍵「開始今天的任務」

首頁一個主要按鈕；已有任務則顯示「繼續今天的任務」，保存同一 queueId，重新整理不重抽題、不重置完成項。

Day1先理解再做入門题；Day2以後按此順序產生固定任務快照：

1. 昨日未解決錯題回想，先不顯示答案，再記錯因（約15分鐘）。
2. 到期複習，以 MUST 及過期程度排序（約15分鐘）。
3. 當日核心短課與每點1–3題即時練習；前置不足則插入2–5分鐘基礎卡。
4. 數字／期限訓練（約10–15分鐘，Day2起）。
5. 混合題／弱點題及檢討，用當日剩餘時間安排。
6. 結束卡顯示「已學、初步掌握、待複習」，可看明日預告。

沒有昨日錯題或到期項目時，時間轉給當日核心，不生成空任務。初次答錯當場解說與變式練習屬修正；下一日再答才是延遲證據。同日重刷同題不能無限抬高掌握度。

同一 queue 中考點去重；前置→MUST→到期補強→SHOULD→OPTIONAL。在日期切換時保留舊快照，新任務只吸收未完成且仍優先的項目。正式考試期間凍結任務規則。

## 5. 課卡、題庫與完成條件

每張短課：白話核心→生活例子→必要術語→必背／混淆對照→1–3題→來源頁碼與重要度原因。完整講義為回查入口；公開建置不打包原始PDF。

內容 tags 可複選：理解、必背、數字／期限、易混淆、計算、情境題、法規題。另設 questionType（單選、組合敘述單選、計算單選、情境單選、回想填答）；「情境」可同時屬法規或計算。

- 已學：讀完短課且完成最低即時練習，不等於掌握。
- 初步掌握：至少3次獨立測量、2個不同題目家族、跨2日，最近最多5筆有效測量正確率≥80%。不足樣本顯示待驗證。
- 數字掌握：另須連同單位、起算條件、適用例外答對；只猜中數字不能完成。
- 當日任務完成：必做隊列完成，不要求全對；錯題移入補強。不得因門檻未達而把使用者鎖在同一天。
- 模考成績、練習成績與答案揭示後重答分开記錄；查看解說後答對不計獨立測量。

題庫來源分「講義原題」「依講義改編」「外部補充」。每題必有 conceptIds、題幹、穩定 optionId、正解、正確理由、各錯項理由、來源／頁碼、題目家族、版本與審核狀態。多敘述題仍只選一個組合選項，不直接改成多選。

本講義原題總計262題。至少四回完整模考不可假設題目充足：需要核實正式規格，建立已審核變式或有來源的補充題。同家族改數字仍視為已曝光家族。生成模考前先檢查各科／各範圍配額，不足就列短缺，不複製題目湊數。

## 6. 錯題與間隔複習

每次提交都保存 attemptId、sessionId、questionId/version、選項、正確性、用時、提示／看答案狀態、時間、模式及題目快照摘要。錯因由使用者選：概念不懂、數字記錯、選項混淆、看錯題目；另允許計算失誤、不確定／猜測、未分類。可多選，系統只提出建議，不憑答案自動斷言原因。

錯題紀錄有 open→recovering→resolved，並保存歷史錯誤次數及最近錯誤。跨2天、2個不同題目家族連續答對後暫移出待處理；再次錯誤重開。刪除收藏不等於刪除作答證據。

複習預設學習後+1、+3、+7日；15天後仍保留到期資料。錯誤時當場補教，下一日重排；對已到期項目重新計算，避免重複提醒。跨日比較用當地日期，時間儲存UTC。

## 7. 獨立數字／期限訓練

每一數字卡結構為：制度／對象＋觸發事件＋起算點＋長度／金額／比例＋單位＋比較符號＋適用版本＋例外＋來源。

練法依次為辨認→配對→反向提問→日期或金額情境。重點不是一串「10、30、180」，而是能說出各自指什麼。

首批分組：保險年齡；等待期與免責期；寬限／停復效；撤銷／解除／終止；通知／理賠／請求時效；傷害級數／短期費率／旅平期間；微型／小額終老；繼承／稅務；登錄／教育訓練／救濟。

日期運算不用天數固定替代月份，必測跨月、月底、閏日及「超過／以上／未滿／翌日」邊界。曆法與法律起算規則有疑義時，題目暫停發布。

## 8. 動態弱點排序

針對已學概念，採：`W = I × E × F × Q`。

- I：章節重要度/100，若是跨章共用概念取來源最高值；MUST最低0.6，SHOULD最低0.3。
- E：最近14天、最多10筆有效獨立測量的平滑錯誤率 `(錯誤數+1)/(有效測量數+2)`；不是把未答當答錯。
- F：`1 + min(max(逾期天數,0)/max(複習間隔天數,1),1)`，值1–2；無到期日預設1。
- Q：`1 + min(關聯講義原題家族數,5)/5`，值1–2。只計講義證據；網路題量與使用者重刷次數都不影響頻率。

尚未學的 MUST 走獨立補缺隊列，不標為「你不會」。冷啟動以講義權重及前置排序；無樣本顯示未測。最近同日同家族只取第一次無提示測量，後續作答仍存檔。

每次挑前三弱點，至少保留20%的混合題抽查其他 MUST，避免永遠困在同一組題。每個推薦顯示具體原因，例如「五星考點、最近5題錯3題、已逾期2天」。

## 9. 考試準備度

是可解釋的學習指標，不是通過機率。0–100分：

`R = 25C + 25A + 25M + 15(1−Erepeat) + 10N`。

- C：MUST考點初步掌握的講義權重加總／全部MUST權重，不以開卡或閱讀次數充數；首頁另顯示MUST已學率。
- A：各MUST考點近期獨立題正確率按重要度加權；未測者貢獻0，並顯示覆蓋率與樣本數。
- M：最近3回完整模考按0.5/0.3/0.2加權；不足3回不重新放大权重，未完成槽位為0。各科有個別門檻時使用最低科別標準化達標程度，不能用總分掩蓋未達標科。
- Erepeat（資料欄位repeatErrorRate）：上次錯誤後，最近一次跨日無提示再測仍錯的考點数／已跨日再測錯題考點數；尚無再測證據時此項貢獻0並標待驗證，不能當作零重犯。
- N：達到數字掌握條件的MUST數字卡權重／全部MUST數字卡權重。

資料不足仍可顯示「暫定分數」，但不能顯示「可上場」。暫用練習卷或考試規格未核實時M不計正式模考分量，標未驗證。分母包含待核對核心考點並顯示內容缺口，不能排除後美化準備度。

建議狀態（教學門檻，可調整）：建立基礎<60；持續補強60–79；接近目標≥80。只有當MUST掌握率≥90%、MUST近期正確率≥85%、數字掌握≥85%、重犯率≤10%、最近兩回完整模考各科均達正式門檻並保有設定緩衝、題庫覆蓋充分時，顯示「目前練習表現達標」。尚未核實的正式門檻一律禁止此文案。

## 10. 模擬考

Day12 A、Day14 B/C、Day15 D；Day13以補強為主。按已核實ExamProfile組卷（科目、範圍、題數、時間、每題分數、各科及格方式）；講義權重用於練習抽題，不能冒充官方配比。

限時、一頁一題、題號導覽、標記稍後、未答提示、提交前確認；交卷後才解說。時間到自動交卷。截止時間存絕對時間，切換背景／重整繼續扣時，無法靠重開延長。

作答逐題持久保存。重啟恢復相同題序、選項順序與剩餘時間；超時則在開啟時立即結算。分頁競爭以session鎖或BroadcastChannel提示接管，防止兩頁覆寫。

報告顯示各科分數與門檻、MUST表現、內容覆蓋、首次家族曝光比例、用時、錯因、前三弱點。熟題太多的分數需標示熟悉度限制，不用作未見題能力證據。

題量不足或未核實規則時仍可做清楚標示的限時練習卷，不能宣稱「完整正式模考」。

## 11. 頁面架構

手機底部五入口：今天／15天／練習／錯題／我的。桌面左側同名導覽，中央學習區；解說在作答後顯示。所有功能均可鍵盤操作，不只靠顏色傳意。

| 路由（Hash） | 頁面 | 核心內容及操作 |
|---|---|---|
| `#/setup` | 首次設定 | 開始日、考試日、時間、考試規格狀態、匯入舊紀錄 |
| `#/today` | 首頁 | 倒數／計畫日、開始今天任務、MUST已學/掌握率、待處理錯題數、前三弱點、模考紀錄、準備度及分項 |
| `#/plan` | 15天計畫 | 每日主軸、時間、完成／逾期／未開始；重排前預览；點入今日清單 |
| `#/task/:id` | 任務播放器 | 當前步驟、所需時間、暫停續做、學習→題目→檢討；不要求自己選章 |
| `#/learn/:conceptId` | 知識卡 | 白話、例子、必背、混淆、來源、重要度、練習與完整頁碼 |
| `#/practice` | 練習入口 | 核心、混合、弱點、章節、10/20題；按時間選擇 |
| `#/numbers` | 數字期限 | 依制度配對、反向回想、日期計算、我的數字錯題 |
| `#/mistakes` | 錯題 | open/recovering/resolved、錯因、次數、相關考點、再次練習 |
| `#/weakness` | 弱點分析 | 排序理由、未測區分、跨章對應、一鍵補強 |
| `#/exams` | 模考入口／紀錄 | 規格與審核狀態、A–D、題量檢查、歷次表現 |
| `#/exam/:id` | 模考作答 | 倒數、題號、稍後、交卷、斷線續作 |
| `#/report/:id` | 模考報告 | 科別、覆蓋、熟題比例、錯題檢討→明日補強 |
| `#/library` | 講義索引 | 12章、150點、MUST/SHOULD/OPTIONAL及標籤篩選；非預設入口 |
| `#/settings` | 我的／資料 | 計畫設定、JSON匯出匯入、離線狀態、版本、重置及備份 |
| `#/sources` | 資料來源 | 講義版本、頁碼規則、外部來源、已知疑義、教材更新記錄 |

### 首頁線框（手機，由上而下）

「15天人身保險考試通關系統」→「Day 6／距考試N天」→「今日180分鐘，已完成35分鐘」→大按鈕「開始／繼續今天的任務」→下一項任務文字→MUST已學率與掌握率→待處理錯題→前三弱點→準備度五分項→最近模考。

避免無資料時顯示0%正確率讓人以為全錯，顯示「尚未測量」。較長文字可展開，按鈕觸控至少44px；最小320px寬不橫向捲動。字體可放大200%，表格在手機改逐項卡片。

## 12. JSON資料與本機紀錄

`learning-data.schema.json` 使用 JSON Schema draft 2020-12。內容包與紀錄包不同根型別；另保留 `concept-catalog.json` 為分析目錄，尚非可發布教材包。

建議專案布局：

```text
src/
  pages/ components/
  domain/ scheduler/ assessment/ exams/
  storage/ validation/
public/data/
  manifest.json chapters.json concepts.json questions.json numbers.json plans.json
public/icons/
docs/                       # 公開部署與操作說明
.github/workflows/pages.yml
vite.config.ts
```

React + Vite + TypeScript；題庫／教材讀JSON；IndexedDB儲存作答、錯題、任務快照及考試，localStorage僅放輕量偏好。純前端，不需要伺服器或帳號。

跨手機／桌面不會自動同步。使用匯出JSON與匯入完成移轉。儲存容量不足時明示並提供匯出，不能顯示成功後丟失。

匯出含schemaVersion、contentVersion、exportedAt、匿名profileId、設定、全部attempts、progress、mistakes、taskQueues、examSessions。匯入先驗證格式、大小（預設20MB）、版本、ID及參照完整性，預覽新增／重複／衝突／孤立項，再選合併或取代。

合併以UUID去重，不累加重複作答；原始attempts為事實來源，統計重新計算。未知教材ID保存在孤立區，勿靜默刪除。取代與重置前自動產生可匯出備份，並以清楚動作確認。

選項綁穩定ID，洗牌不改正解；題目變版後保留舊次數與版本快照。修正錯答案後可標記舊測量失效，重算準備度但保留歷史稽核。

## 13. PWA與GitHub Pages

- 使用Hash路由處理Pages深層連結；Vite base 支援 `/<repo>/` 與根網域，manifest start_url/scope及圖示、JSON與service worker路徑跟隨base。
- `vite-plugin-pwa` 管理manifest與service worker。首次成功載入後預快取程式與指定版本教材包；離線可做今日任務、答題、看已安裝內容、計時及存紀錄。
- 明示教材「已下載可離線」及版本；外部來源連結無法離線時顯示原始書目及網路需求。
- 更新先下載完整新版，檢驗版本一致再切換；正在模考／作答時不強制重載。新版可用顯示提示，作答完成再套用。舊版保留至無活躍session，避免題目半套更新。
- 手機安裝入口按瀏覽器能力提供；iOS給分享→加入主畫面說明，不保證所有瀏覽器有相同安裝按鈕。
- GitHub Actions以鎖檔安裝依賴、型別检查、建置並部署dist。提供使用者建立repo、啟用Pages Actions、base設定及排錯說明；交付專案不等於已代為上線。
- 原始PDF、OCR、使用紀錄與內部訓練資料不納入公開建置或公開Git。講義標有「僅供內部訓練使用」；公開內容以自行撰寫且已審核的教學摘要／變式及可使用的補充來源為主，原題可作本機內容包。不是要求使用者此刻另外核准，而是部署包的明確範圍。

## 14. 題庫與內容驗收

1. 114頁都有盤點紀錄；12章星級對照目錄，章末題號與答案頁對照，跨頁題不漏算。
2. 150考點都有頁碼、優先級、標籤、建議日及成果；可追溯A+及原題，不以網路題量加權。
3. 每一發布題逐題核對題幹、四選項、答案、解析、條件與來源。答案表不完整或與正文矛盾者隔離。
4. 法規／稅務數字增加版本、適用日期與官方查核連結；講義版與核實規定有差異時並列，不静默覆蓋。考試採用版本未定則不上正式模考。
5. 先建立足够題目家族再開模考；可重複用於練習，但同家族曝光要揭露。

## 15. 實作驗收與測試

優先測核心資料和使用流程，不為靜態文字改動建立鏡像測試。

- 任務：Day1順序、無錯題、漏一天、跨午夜、重開續做、Day14兩回、Day15不加新課。
- 評量：未測不當錯、同日同家族不灌分、錯题跨日解決又重開、五分項資料不足、科目最低門檻。
- 日期：最近生日法、月份與天數、閏日、翌日、停復效邊界；每種題獨立驗算。
- 模考：背景倒數、重整、過期自動交卷、未答計分、答案延後顯示、題量不足阻擋、選項洗牌。
- 資料：匯出再匯入等價、重複匯入不翻倍、舊版遷移、壞檔不污染資料、配額不足提示。
- PWA：首次線上下載後離線重開並完成任務；教材與程式更新一致；考試中更新不打斷。
- Pages：以repo子路徑預覽，直接開hash深連結、重整、圖示、JSON及SW皆正常。
- 裝置：320/390px手機、768px平板、1280px桌面；鍵盤、觸控、字體放大、對比、焦點、讀屏答案回饋。

## 16. 確認後的實作順序

1. 確認本規格；補正式考試識別資訊，取得可用規則來源。未確認不假設門檻。
2. 建立React/Vite/TS專案與JSON驗證、資料儲存、今日任務及15天課表。
3. 完成MUST短課與逐題審核，先連通「學→答→錯因→明日再測」。
4. 數字訓練、弱點與準備度、模考、匯入匯出。
5. PWA、手機／桌面與Pages驗收；交付原始碼、部署流程及內容版本說明。

規格確認是使用者原始要求的階段關卡，不是工具或技能額外增設的批准程序。
